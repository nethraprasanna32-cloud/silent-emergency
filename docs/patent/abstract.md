Silent Emergency Database (SED) provides database-resident inference and allocation of social assistance needs from heterogeneous, consent-governed events. Transactional triggers append entity changes to an outbox. A worker claims events with row locking and evaluates affected entities and spatially related candidates. Signal contributions decay with age and are compared with versioned rules; need state changes are retained as temporal history. The system represents assistance resources and volunteers as constrained candidates and records match explanations, alternatives and expiring reservations. Serializable assignment transactions lock scarce inventory and volunteer records, update need status and write an audit event atomically. Configured local-file mappings support staged ingestion, while provenance and rejected-row records support review. A hash-linked audit log provides tamper detection. The architecture supports offline deployment using PostgreSQL and PostGIS.
