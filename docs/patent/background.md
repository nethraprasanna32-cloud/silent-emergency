# Background

Many assistance workflows begin only after a person explicitly asks for help. This leaves silent or isolated people dependent on discovery by another party. A second technical limitation is greedy allocation: choosing the locally best candidate repeatedly can consume scarce inventory while leaving globally better combinations unused. Re-scanning large datasets after each change adds query cost and delays.

SED's technical problem is to infer unrequested needs from heterogeneous signals, re-evaluate only affected deltas, allocate assistance fairly using global optimization, and reserve scarce resources consistently.
